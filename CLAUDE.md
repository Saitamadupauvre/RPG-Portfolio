# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

3D portfolio site, two entry modes reached from a menu:
- **Game mode**: free-roam 3D world (open world, not linear), meant to be a *real* game â€” moderate difficulty, enjoyable, a bit of challenge. No win/end condition (it exists to show projects). A final boss is planned but not scoped yet. Enemies, statues, items, and props are placed by hand as level design â€” never auto-generated from the project list.
- **Fast portfolio / classic mode**: flat list of every entry in `src/data/projects.ts`, independent of what's placed in the game world, for recruiters who don't want to play a game.

Visual split: **3D low-poly** for the game world (Three.js meshes), **2D pixel-art** for all UI/menus/overlays (hand-rolled DOM+CSS, no canvas renderer). Pixel look is currently CSS-only placeholders (`src/style/pixel-ui.css`: blocky monospace, hard-edged panels, stepped shadows) â€” swappable for real pixel-art PNGs/font later without touching component structure.

Stack: Vite + TypeScript + Three.js. No framework (no React/Vue) â€” DOM is manipulated directly via `document.getElementById`/`document.createElement` etc, Three.js owns the WebGL canvas.

## Commits

Commit messages: one line, conventional-commit style (`feat(scope): summary`, `fix(scope): summary`), no attribution/co-author lines.

## Commands

- `npm run dev` â€” start Vite dev server (port 3000, see `vite.config.ts`)
- `npm run build` â€” `tsc` (type-check only, `noEmit`) then `vite build`
- `npm run preview` â€” preview the production build
- `npx tsc --noEmit` â€” type-check only, useful after any change since `strict` + `noUnusedLocals`/`noUnusedParameters`/`noFallthroughCasesInSwitch` are all enforced and `npm run dev` does not type-check
- No test runner is set up yet.

## Architecture

Layered, event-driven â€” each layer only knows about the layer below it via typed events, not direct references: `core` â†’ `data` â†’ `domain` â†’ `game`/`ui` (the latter two never reference each other). `audio` sits beside `core`: both `game` and `ui` may play sounds through it.

- `src/core/` â€” framework-agnostic infra, no Three.js/DOM knowledge. Imports nothing from other layers (type imports from `data/` only).
  - `EventEmitter.ts` â€” generic typed pub/sub (`EventEmitter<Events>`), has `on`/`off`/`once`/`emit`.
  - `events.ts` â€” `AppEvents` type map + one shared `events` singleton. Add new cross-layer events here. `projectDiscovered` = first-time discovery (book refresh); `projectShown` = open the book on that project's page; `levelUpRequested` = open the book on the Level page; `levelUpAvailableChanged` = player in/out of bonfire range (stats buyable only then); `tutorialShown` = open the book on that tutorial's page. Death is a handshake: `playerDied(coinsLost)` (player whitening/fading, HUD coin loss), then `playerFaded(x, y)` once the body is gone, the iris closes there and emits `respawnRequested` once the screen is black; `World` then moves the player and emits `playerRespawned(x, y)`. Resting is the same handshake: `restRequested` (bonfire) -> `restStarted(x, y)` (world paused, iris closes) -> `restCovered` (heal + enemy reset under black) -> `playerRested(x, y)` (iris opens). `gameEntryCovered` = Game picked before `worldReady`: the menu faded to black, so the entry cuts instead of gliding, even if the world got ready during the fade. `gameEntered` = world ready after such an entry, camera already in its gameplay shot (the black fades out, no circle). `worldReady` = the background boot finished: the world now stands behind the menu and Game starts with a camera glide instead. `loadingProgress` (0..1) drives the boot screen. `PromptAction` names an `InputAction`, never a key code, so prompts follow rebinding.
  - `StateMachine.ts` â€” tracks `AppState` (`LOADING | MENU | GAME | CLASSIC | DEAD | EDITOR`) and emits `stateChange`. Does **not** touch the DOM.
  - `pause.ts` â€” `setPaused(reason, paused)`: pause is a *set of reasons* (`book`, `rest`), emits `pauseChanged` only when the aggregate flips. `isGameplayActive()` = state `GAME` and nothing paused; every global gameplay input listener checks it.
- `src/data/` â€” pure content, no game-mechanics or rendering knowledge, never imports from `domain`/`game`/`ui`.
  - `Project.ts` / `projects.ts` â€” `Project` type + hardcoded `Project[]`. Pure content: no placement, no region, no discovery info. Single source of truth for classic mode, the in-game book, and statueâ†’project resolution.
  - `MapEntity.ts` â€” tagged union (`kind: 'enemy' | 'chest' | 'item' | 'prop' | 'statue' | 'bonfire' | 'trigger'`) + `ChestLoot` and `TriggerAction` unions. A trigger is a box volume sized by its `scale` (unit box, x/z centred, y from the ground up). Placement lives here, never in `projects.ts`; a `projectId` on a map entity is the *sole* coupling point between world and project data.
  - `mapLayout.ts` â€” every hand-placed entity, one flat list, read from `mapLayout.json` (the editor's Export map, dropped over the file as is; cast through `unknown` since JSON arrays are not tuples). Runtime chunk membership is derived from position, never authored.
  - `tileMap.ts` â€” terrain as integer levels per tile + `waterLevel`, read from `tileMap.json` (the editor's Export map downloads it with `mapLayout.json`); `resizeTileMap`.
  - `sounds.ts` â€” `SOUNDS` table, one entry per `SoundId` (derived from the keys): `files` (several = random variant, never twice in a row), `bus` (`sfx`/`music`/`ui`/`ambience`), `volume`, optional `pitch` range, `volumeJitter`, `maxVoices`, `cooldown`. Files live in `public/audio/<bus>/`. `TRACKS`: looping music/ambience (`file`, `bus`, `volume`).
  - `stats.ts` â€” `StatId`, `PlayerStats`.
  - `tutorials.ts`: `TUTORIAL_IDS`; each id is also a `tutorial` page id in `pages.ts` (`validateBook` checks it).
  - `BookPage.ts` / `pages.ts`: free-form book pages; optional `image` (path under `public/`), `controls` (keycaps, `'MouseLeft'` = mouse, `shape: 'cross'` = WASD block) and `tips`. Tutorial screenshots live in `public/tutorial/`, captured headless (player centred, 400x225 crop at 0.8 scale). `ControlHint.actions` (one per key) draws the player's current keys instead of `keys`.
  - `settings.ts`: preference types only (`InputAction` ids, `KeyBinding` = `code` matched + printed `label` shown, `Quality`, `Settings`), here so `core/events.ts` and book content can name them.
  - `loadingTips.ts`: one-line tips rotated on the loading screen.
- `src/audio/audio.ts` â€” Web Audio player, imports only `data/sounds.ts`. `initAudio()` (from `main.ts`: builds master -> bus gains, decodes every file, resumes the context on the first click/key, autoplay policy), `playSound(id, { volume, pitch, delay })` (no-op while locked or still loading), `setVolume(bus | 'master', v)` (slider position, squared into the gain, short ramp). `playTrack`/`stopTrack(id, fade)`: `TRACKS` stream from an `<audio>` element through a `MediaElementSource` (never decoded whole), fade on their own gain, pause once silent; asked while locked, they start on the context's `statechange` to running. The context suspends in a hidden tab. `main.ts` applies volumes (`CHANNEL_BUSES`: the `sfx` slider drives `sfx` + `ui` + `ambience`) and plays `mainTheme` + `worldAmbience` in every state but `CLASSIC` (no settings page there to turn them down). Third-party credits in `CREDITS.md`. Hooks: footsteps = `footstep` clip events on the player's Walk (frames 3 and 9), sword = `AttackComponent` `onAttackStart`, dash in `DashComponent.trigger`, hits in `CombatSystem`, coins in `HudView` (gains only), page turns in `pageFlip` (first 3 leaves).
- `src/domain/` â€” pure derivation, no Three.js/DOM imports (localStorage only through `persistence.ts`).
  - `persistence.ts` â€” `loadJson`/`saveJson` + `createPersistentSet(key)`; used by `discovery`, `openedChests`, `defeatedBosses`, `slainEnemies` (regular kills, cleared by a rest or a death: chunk reloads keep them dead), `checkpoint`, `playerProgress`, `settings`. `clearSave()` wipes every `rpg-portfolio:` key except `settings` and `editor-*` (by prefix, so a new save file cannot be forgotten); the caller reloads the page.
  - `playerProgress.ts` â€” coins + stat levels, upgrade costs, `getPlayerStats()`. Saves are *merged* onto defaults per field, so adding a stat never wipes old saves. `loseAllCoins()` on death.
  - `settings.ts`: rebindable keys (`rebind` swaps with whichever action held the key, refuses reserved ones), quality, screen shake, `volume` per `VolumeChannel` (`music`, `sfx`; `setVolume` emits `volumeChanged`, not `settingsChanged`, so dragging a slider never redraws the book); merged per field like progress, emits `settingsChanged`. `keyFor(action)` is what every input listener compares `event.code` against.
  - `input.ts`: `ARROW_KEYS` always move, on top of the rebindable `up/left/down/right` actions. Codes name a key by *position*, so the default WASD codes are ZQSD on AZERTY: no layout setting (an old `KeyZ`/`KeyQ` "AZERTY" table was wrong and is gone); defaults carry an empty label and the UI names them from the real layout. `isReservedKey` (arrows, Escape, Tab, OS key, F row), `keyLabel(code)`, `labelForKey(event)` (the printed character).
  - `chestLoot.ts` â€” one handler per `ChestLoot` kind (mapped type forces exhaustiveness).
  - `triggerActions.ts`: same pattern per `TriggerAction` kind. `tutorial` emits `tutorialShown` only the first time (`seenTutorials` persistent set).
  - `chunks.ts` â€” `CHUNK_SIZE`, `chunkKeyAt`, `bucketByChunk`, `keysInRadius`.
  - `CardStyle.ts` â€” `projectToUICardStyle(project)`, `rarity`-keyed presentation lookup for UI cards only.
  - `components/` â€” engine-agnostic component logic: `Component.ts` base interface, `HealthComponent.ts`.
  - `collision/CircleCollision.ts` â€” pure circle-vs-circle push-apart resolution.
  - `pathfinding/` â€” `NavGrid.ts` (`worldToCol`/`worldToRow` *clamp*, so use `isInsideBounds` for the map edge; `canTraverse` predicate for cliff steps) + `AStar.ts` (binary-heap open set from `MinHeap.ts`; the start cell is dropped from the returned path).
  - `terrain/TileGrid.ts` â€” heights derived from tile levels (1 level = ramp, 2+ = cliff); `heightAt` reads the same two triangles per tile the renderer draws (split on the c00â†’c11 diagonal).
  - `animation/` â€” Unity-style animator, engine-free half. `AnimatorController.ts` (definition: parameters bool/float/trigger, layers with bone-name `mask`, states naming a clip as exported from Blender plus `loop`/`speed`/`speedParam`/`markers` (seconds)/`events`, transitions with conditions/crossfade `duration`/`exitTime`/`'*'` any-state; `validateController` throws on typos), `AnimatorParameters.ts`, `AnimatorLayer.ts` (per-layer state machine: crossfade weights, interruption-safe fading list, event firing; learns clip lengths through a `DurationLookup`).
- `src/game/` â€” Three.js scene graph and interaction.
  - `Experience.ts` â€” owns scene/camera/renderer/render loop; instantiates `World`, `PlayerAttackInteraction`, and (dev only) `EditorSystem` (F1). `Experience.init(canvas, portraitCanvas)` once (lazily, from `main.ts`, on first `GAME` entry) + `getInstance()` elsewhere; it also creates the `PlayerPortrait`. Frame delta is clamped (`MAX_FRAME_DELTA`) and the timer is connected to page visibility. Shadow map `autoUpdate` is off and flagged once per tick, because the water depth prepass renders the scene a second time. `QUALITY` presets (pixel ratio, shadows, grass) applied by `applyGraphics` from settings; in dev the perf overlay's switches can only turn more off. Nothing is rendered outside `MENU`/`GAME`/`DEAD`/`EDITOR` (the canvas is hidden in classic mode, and in the menu until `worldReady`).
  - `assetLoading.ts`: `watchAssets()` hooks `THREE.DefaultLoadingManager` (every glTF goes through it) before the world is built, so the boot screen waits for the models (12 s cap) instead of revealing placeholders.
  - `portrait/PlayerPortrait.ts`: the live knight on the book's Level page. A second, small `WebGLRenderer` (transparent, `preserveDrawingBuffer` so page turns can copy its last frame) with its own scene: world-matching lights, a `ShadowMaterial` floor (only the shadow shows on the paper), the player model through `loadPlayerModel`, its own `AnimatorComponent` idling. Draws only while its canvas is on screen (`IntersectionObserver`, plus a computed `visibility` check for the phone layout), sizes itself with `ResizeObserver`; drag sideways to turn it, it eases back to `REST_YAW`. A second context because a context only draws into its own canvas and the game's has no alpha.

  - `entities/StatueFactory.ts` / `ChestFactory.ts`: primitive placeholder until `statue.glb` / `chest.glb` load, both built by `tools/blender/make_world.py` (local-only) in game units, so `STATUE_HEIGHT` / `CHEST_HEIGHT` are their Blender heights. The game finds parts by name: the statue glows through its `Gilt` (crest, sword, plaque) and `Carving` (visor slits, eyes) materials, lit whole it would lose its shape; the chest's lid hangs from a `Lid` node at the hinge (rotated about X to open), `Trim` is recoloured per tier (`steel` silver, `gold` gold) and `Lock` glows until opened.
  - `entities/EnemyPool.ts` â€” per-`enemyType` stat/look table and Entity pooling; `attack` is `lunge | combo | shoot | breath`. `init(camera, player, entityGroup, projectiles, fire)` must run first (throws otherwise). `reset(entity, source)` = back to just-spawned (health, flash, swing, AI, transform, `animationDriver.reset()`), shared by acquire and bonfire rest. `createFighter` builds each attacker together with the factory of its animation driver (no `instanceof` matching later).   - `animation/` â€” Three half of the animator. `AnimatorComponent.ts` (built from the controller alone, `bind(rig, clips)` once the glTF arrives; blends layers bottom-up with lerp/slerp from the bind pose, masks by bone name, reads each layer's active states once per frame; API: `setBool/setFloat/setTrigger`, `play`, `setTime`, `overrideClip`, `on(event)`), `sampleClip.ts`, `Rig.ts` (`collectRig`, `equip`).

  - `world/windStreaks.ts` — stylized wind ribbons (cream, some curl into a loop), one instanced draw call. The path is a function of time in the vertex shader (tail = the head's past position), driven by the shared wind uniforms; the CPU only respawns a streak round the player when its life ends, above the highest ground/water along its way. Own `WIND_LAYER` (kept out of the water depth prepass); count per `QUALITY` preset (off on low).
  - `world/water/` â€” endless sea plane, depth prepass, heightfield texture, water shader. The swell drifts downwind at a fixed slow speed (bob rate), its height scales with wind strength; the wind's speed shows only as normal-map ripples, never as faster bobbing.
  - `world/Environment.ts` â€” sky, fog, lights. The shadow camera follows the player (`followShadows`), snapped to whole shadow texels. `setShadows` goes through `sun.castShadow`: flipping only `renderer.shadowMap.enabled` does not recompile materials, which keep sampling a frozen map. Light intensities are exported for the portrait.
  - `world/navigation.ts` â€” shared nav grid: collidable props/statues/bonfires block cells, underwater ground blocks cells, cliff steps via `canTraverse`.
  - `world/obstacles.ts` â€” the same collidables as upright cylinders (factory radius, real heights, `heightOffset` as the bottom), bucketed; `isNearObstacle` adds a margin (menu camera). For arrows, since half-unit nav cells left arrows hanging beside thin trunks. Rebuilt with the nav grid in `World.refreshFootprints`.
  - `editor/` â€” dev-only map editor (`EditorSystem`, `editorLayout` localStorage working copy, `TileSelection`, `entityDefaults`). The working copy replaces the committed map only once the editor is first opened. Unity-style mouse: left = select/box/brush, right = orbit, middle = pan. Multi-selection moves through a shared `pivot` (offsets captured once per drag). Triggers are picked by their edges only (fill `raycast` disabled) and left out of the scatter brush; their action is edited by the inspector's `actionEditor` (`actionFieldByKind`). `scatter.ts` (scatter brush stamps/erase, erases only what its entries paint), `brushVisuals.ts` (cursor ring, ghosts until release: the world is rebuilt once per stroke, not per stamp), `UndoHistory.ts` (whole-state snapshots, 50 deep). Brush settings types live in `core/editorTools.ts`.
- `src/ui/` â€” DOM/HTML layer, reacts to `core/events.ts`, no Three.js imports.
  - `UIStateView.ts` â€” `stateChange` â†’ `state-<name>` class on `#ui-container` and `body`.

Every other interface lives inside the book.
  - `components/` â€” book rendering: `renderBookToc`, `renderBookEntry`, `renderLevelPage` (the live knight's canvas + stats), `renderSettingsPage` (Controls left, Options right; key capture listens on `window` in the capture phase and stops the event, so Escape/B never reach the book), `renderKey`, `printedKeys` (`keyName(binding)`: Keyboard Map API, then the binding's saved label, then an AZERTY guess from the language), `pageFlip` (leaves carry clones of the pages; cloned canvases are repainted from their originals), `formatDate`. `iris.ts` = the one iris overlay (`close`/`cover`/`uncover`/`reveal`/`clear`; a new call interrupts the old, whose promise resolves `false`; `close` starts from the current circle when one is up). `pixelSprite.ts` draws `sprites.ts` (character grids + palette) as crisp SVG, frames side by side as a sheet stepped in CSS (`.sprite-play`).

## Design decisions locked in

- **Map vs. project data are separate concerns.** Level content is placed and typed on its own in `mapLayout.ts` â€” never auto-derived 1:1 from `projects.ts`. The only link is an optional `projectId` on a map entity, resolved at interaction time.
- **Entity/component pattern**, not per-type subclassing. Player, enemies, and future entity types reuse the same `Entity` base plus attachable components.
- **Boss vs regular enemy**: `enemyType` is authored per `MapEntity`, not derived from `Project.rarity`.
- **Combat depth**: full action combat â€” movement, attack timing/hitboxes, health bars. Built incrementally; hit detection, combos, AI, and juice (particles/shake/flash) already exist.
- **Pixel UI via hand-rolled DOM+CSS**, not a canvas-2D renderer. `image-rendering: pixelated` + `border-image` 9-slice framing is the intended mechanism once real art exists.
- **Project data**: hardcoded typed array in `src/data/projects.ts`, ~5-10 projects. No CMS/backend.
- **Deploy target**: static build â†’ GitHub Pages / Vercel / Netlify. No server-side code.

## Conventions

- TypeScript config: `strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch` all on â€” keep code clean enough to satisfy these, don't loosen them. Run `npx tsc --noEmit` after changes.
- Prefer a `type` alias over `interface` for anything used as a generic constraint â€” `interface` allows declaration merging so TS can't prove it has no extra keys. Exception: plain data-shape interfaces meant to be `implements`ed (e.g. `Component`), which need at least one non-optional member for TS's weak-type check.
- Singletons: module-level `export const instance = new X()` when construction needs no external input (`EventEmitter`, `StateMachine`, `EnemyPool`). `private constructor` + `static init(...)`/`static getInstance()` when it needs input available only later (`Experience` needs the canvas).
- Discriminated unions (tagged with a `kind` literal) over one flat interface with many optional fields.
- File layout: `src/core/` = framework-agnostic infra. `src/data/` = pure content, never imports other `src/` layers. `src/domain/` = pure derivation from `data/`, no Three.js/DOM. `src/game/` = Three.js scene graph. `src/ui/` = DOM layer. `game/` and `ui/` never import each other â€” only through `core/events.ts`.
